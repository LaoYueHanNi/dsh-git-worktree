# DR: 工作树会话的菜单作用域三分（展示/提示/仅当前分支）

Status: implemented

## Problem

本主题的第一版落地是"灰显锁定"：worktree 会话里非当前分支全部 HTML disabled，hover 的 title 给出原因——当时已确认 worktree 会话不该原地切换（会 dissolve「目录 = 分支」的身份：目录里跑的不再是名义分支，未完成编辑与对话上下文错配）。但灰显形态留下三处别扭：disabled 行点击毫无反馈，整片灰读起来像"坏了"；空白的工作树会话居然还挂着「工作树」开关——在一个 worktree 目录里发起另一个 worktree，发起语义放错了工作区；同理，原地新建分支（`switch -c`）也会在该 worktree 原地建分支并检出，同样违反约定，却没有被第一版锁定覆盖。

## Decision

worktree 会话（会话 toplevel ≠ 主 worktree 条目）的入口收敛为三分作用域：

1. **已启动**：菜单只展示会话自己的分支（本地组单行 + check，远程/工作树组不渲染）——菜单退化为位置标记 + 提取/更新工具（两者都不动检出）。
2. **未启动**：全部行照常展示、可搜索，**非当前分支行置灰**（`.menuRowLocked` 样式类，刻意不用 HTML disabled——禁用按钮会吞掉点击，提示就永远无法触发），但**一切动作**（本地/远程确认、工作树组跳转、新建分支）在 owner 的 `onSelect` 统一拦截，toast 一句话指回主仓库：「分支操作请在主仓库发起」。三重反馈：置灰一眼可辨"这里不可用"、hover title 给出原因、双击的 toast 给出出路。单击不选中（灰显行穿蓝色选中态会读成"已选但不可用"）。
3. **工作树开关只在主仓库的空白会话渲染；原地新建分支按钮（plus）在主仓库会话常驻，两种时刻收起为不渲染**：勾选了工作树开关时（正在发起 worktree，原地建分支的入口退场——两个"创建"动作不并置），以及工作树目录里（发起 worktree / 发起新分支都是主仓库的决策，工作树目录里这两件工具都不在）。收起一律是卸载而非 `disabled`——禁用按钮吞点击无反馈，正是本 DR 自己反对的形态；create 弹层的 Escape 与 outside-click 收起路径不依赖按钮存活。

置灰以样式类落地（非 disabled 属性，点击路径保持存活）：拦截集中在 `onSelect` 一处，行组件仍是纯数据。

## Alternatives considered

- **维持第一版 disabled 灰显锁定**——disabled 按钮吞点击，提示永远无法触发，"为什么点不动"只能靠 hover 发掘；且覆盖不了开关与新建分支两个漏网入口。样式灰显 + toast 的组合两全。放弃纯 toast 无置灰：不可用的行不作视觉区分，扫视时与可用行无差。
- **只拦截确认弹层、把弹层换成说明性文案**——为"做不了的事"弹一个对话框是仪式负担，且弹层只覆盖弹层路径，工作树跳转/新建分支仍需各自拦截；toast 单点覆盖一切动作。放弃。
- **仅锁定已启动会话、空白会话放行**——空白会话切走分支同样解绑目录身份，且此时正是挑环境的时刻，锁定语义一致更可预期。一并锁定（已启动则干脆只展示当前分支）。
- **started 会话也全量展示 + toast 拦截**——started 会话根本没有任何可执行动作，展示几十行不可操作的分支是纯噪音；只留当前分支，菜单即诚实。放弃。
- **工作树开关保留在 worktree 空白会话**——从 worktree A 勾开关切出新分支的起点是 A 的检出，语义上仍是"在 worktree 里发起"，与"目录身份不可动"矛盾；统一归主仓库，规则无需解释。放弃。
- **提示带主仓库路径/名称**（"请在主仓库 D:\... 发起"）——toast 一闪而过，长路径读不完；动作出口用户本就知道（侧栏第一个工作区就是）。放弃。

## Consequences

- 得：worktree 会话的菜单语义一眼可辨（started = 我在哪；blank = 可看不可动）；拦截集中单点；工作树/新分支的发起语义全部归位主仓库。
- 代价：blank 工作树会话连"跳到别的 worktree"也要回主仓库（多一跳）；started 菜单只剩一行，搜索/定位工具几乎无用武之地（保留，无成本）。
- 边界：拦截只作用于本插件的菜单——终端里在该 worktree 任意操作插件不感知；锁定判定基于打开菜单时的 status 快照，worktree 新建/删除不即时反映（与全菜单的拉取口径一致）；toast 不区分动作类型，是刻意的一致性代价。
