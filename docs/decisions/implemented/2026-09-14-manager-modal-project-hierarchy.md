# DR: 管理工作树弹窗的项目-工作树从属视觉层级

Status: implemented

## Problem

`WorktreeManagerModal` 在数据上早已按所属仓库分组（`scan-groups.ts`，组名字母序、组内按分支名排序），但呈现层只有一个 12px 加粗的裸文字组头，与条目的分支名（13px/500）在字号字重上几乎无法区分，组与组之间也只有一条 hairline。用户打开弹窗看到的是"三个并列条目"，分不清哪个名字是项目、哪些名字是工作树，更看不出"哪个项目拥有哪些工作树"——分组语义只存在于代码里，不存在于屏幕上。

## Decision

从属关系改为**结构性表达**，全部在呈现层完成，不动 `scan-groups.ts` 的数据契约：

1. **一个仓库 = 一张卡片**：`.group` 升级为圆角描边容器，滚动容器 `.list` 自身去边框、组间 10px 间距——外框包裹卡片的旧结构会让所有内容读回一个平面列表。
2. **组头升级为色块标头**：浅色填充条（`--dsw-alias-bg-layer-2`）+ 文件夹图标（`IconFolderClose16`，与侧栏工作区分组同款视觉语言）+ 仓库名 + 右对齐的工作树数量徽标（复用 `manager.count` 文案，"dsh-token-usage · 2 个工作树"一眼读完归属与规模）；`overflow: hidden` 把色块裁进圆角。
3. **条目缩进**：行左内边距 29px = 组头 10px 内边距 + 13px 图标 + 6px 间距，行内容与组头**文字**精确对齐，行在读感上"装进"所属项目卡片的内部；组内行间保留 hairline，末行去除。

无法识别目录的殿后组共用同一卡片样式（头为 `manager.orphans` 文案），但不显示数量徽标——它们不是工作树，`manager.count` 对它们语义为假。

## Alternatives considered

- **每行内重复显示所属项目名**（改数据、行内徽标）——2026-09-13 的记录已明确"行内不再重复项目名"；行内重复 N 次同一个词是噪音，且仍无法表达"集合归属"。放弃。
- **树形折叠组件（可展开/收起的项目节点）**——管理弹窗的典型规模是几个仓库、每个一到数棵工作树，折叠交互收益为负（多点一次才能看到全部）；且 GroupedSidebar 的树形分组已有现成入口，弹窗的定位是跨仓库全景一览。放弃。
- **只加大组头字号字重，不加容器**——最小改动，但纯排版差异仍是"两个级别的文字"而非"容器与内容"，从属关系依旧靠猜。放弃。
- **颜色区分不同项目**（每个仓库一个色相）——颜色是稀缺语义资源，本弹窗已用红/黄承载 dirty/warn 语义；项目间用颜色区分没有信息增量（分组已表达），只会引入任意配色。放弃。

## Consequences

- 换来：项目与工作树的归属关系从布局本身可读，无需阅读文字猜测；每组规模（几个工作树）无需逐行数。
- 代价：卡片描边 + 色块标头比原设计多一层视觉重量，弹窗在只有单一仓库时也呈现一张卡片（接受——单卡片与"管理工作树"的语境仍自洽）；行缩进 29px 使有效内容宽度略窄（对话框 680px，可忽略）；数量徽标对含大量工作树的单仓库只是数字（不折叠，接受）。
- `scan-groups.ts` 与 `/worktrees-all` 契约零改动，`prune-history` 等其他视图不受影响。
