# DR: 从分支菜单原位展开提交图谱

Status: implemented

## Problem

分支菜单只能浏览分支与执行分支操作，查看所选分支的提交历史及合并关系需要离开会话界面。只显示提交首行无法理解改动背景，但直接铺开完整正文又会挤占历史列表。

## Decision

顶部工具行按分支名、作者筛选、紧凑搜索框、已加载提交计数排列，分支名使用较大的 14px 半粗字体，不显示“提交图谱”标题或独立搜索行。搜索提示“文本或哈希”，作者下拉框按已加载提交的作者去重，默认全部作者，可与文本查询叠加。列表底部仅在有后续页或读取错误时显示加载更多或重试，避免单独的计数行占用列表空间。

右上角使用宿主叉号图标，名称为“关闭弹出的窗”，仅关闭整个分支浮层。图谱模式在当前组件存续期间跨浮层关闭、重开保留；只有左侧“打开图谱 / 关闭图谱”按钮改变模式，外部点击与 Escape 关闭浮层均不重置模式。

展开和收起使用 220ms ease 尺寸及位置过渡，在按钮上方的紧凑菜单与视口居中的图谱之间平滑切换。以实际测量尺寸驱动动画，使紧凑模式仍能按分支数量自适应高度；快速反向切换从当前帧继续，关闭菜单清理动画，系统启用减少动态效果时直接切换。

在 `BranchMenu` 左侧工具栏、定位当前分支按钮上方提供图谱按钮。展开后同一浮层优先垂直居中，横向对齐所属输入框卡片中心，宽度不超过该卡片的实际宽度及 1060px，高度最大 700px，视口四周至少留 12px。图谱和普通分支菜单的下边界均不得低于输入框卡片顶部减去 6px，空间不足时图谱向上让位并按实际可用空间缩短，保持输入区完整可见。通过宿主 `data-composer-card` 测量边界，并使用 ResizeObserver 监听卡片和所属对话容器，跟随可调对话宽度、输入框高度、侧栏和窗口变化，不复制宿主宽度设置算法；尺寸变化立即取消旧的展开动画，避免旧动画在新边界外继续播放。左侧沿用分支树和搜索，右侧 `CommitGraph` 展示所选分支可达的提交、真实父提交连线和底部详情。沿用宿主菜单的圆角、半透明材质、主题变量与选中态；窄视口隐藏作者和哈希辅助列。

浏览分支与检出分支分离：图谱模式单击、方向键和 Enter 只选中浏览分支，检出仍由显式的行右键菜单执行。当前检出分支的勾选不随浏览移动；远程分支按完整 `refs/remotes/...` 读取，工作树行按对应本地分支读取，脱离分支的会话按该工作目录的 HEAD 读取。沿用现有会话可见分支集合和分支操作权限。

宿主提供只读 POST `/history` 和 `/commit`，统一使用现有路由错误封装及可注入的 Git 执行器。前者仅接受显式本地/远程分支引用或 HEAD，以拓扑顺序每页返回 100 条，额外读取一条判断是否有下一页；首屏解析出的提交 OID 固定后续页，避免分支移动造成分页错位。后者仅接受完整 OID，返回完整正文和第一父提交口径的文件统计（根提交与空树比较），仅返回首个文件名、文件数、增删行及二进制文件数，不读取补丁。初始分支无提交时展示空态，失效引用或读取失败有错误和重试入口。不会访问远程、切换工作目录或修改工作区文件。

图谱按整个已加载前缀分配节点与连线，分页追加不移动已有节点；父提交尚未加载时连线延续至页面边界。搜索明确限定为已加载提交的标题和哈希，不匹配作者；作者由独立下拉框筛选。任一过滤条件生效时隐藏连线，避免跳过中间提交后虚构关系。切换分支、刷新或选择其他提交会中止旧请求并丢弃旧响应。

筛选结果和实际选中项在一次线性遍历中计算，避免逐行扫描整个列表的平方级开销。当前选择被过滤掉时显示首条匹配提交，无匹配时清空详情；详情响应的 OID 必须与实际选中项一致才可展示，避免过滤切换时短暂展示旧详情。文件统计显式禁用 Git 的相对目录模式，保证会话位于仓库子目录且配置了 `diff.relative=true` 时，根提交和普通提交仍返回整个仓库的摘要与路径。

完整正文保留换行，默认最多三行且省略溢出，仅实际超出时提供“展开正文”。详情横向铺满右侧面板底部；展开后详情区的**高度**最多占右侧面板高度的 44%（且不超过 316px），正文内部滚动。这是纵向限高，不是正文或详情区的限宽要求；切换提交恢复缩略态，无正文有明确提示。Escape 先处理现有行菜单/确认/命名浮层，再清空提交搜索、清空作者筛选、收起正文、清空分支搜索，随后恢复原有选择/菜单关闭逻辑。提交列表的键盘事件与分支操作隔离。

正式组件通过宿主接口读取实时数据。

## Alternatives considered

**单独打开全屏 Git 窗口，完整模仿 IDEA 三栏布局**：不符合原位扩大现有弹层的需求，且与宿主风格不同。IDEA 仅作为分支和图谱布局参考。

**保持窄弹层，把提交列表放在分支树下方**：不足以并行查看分支、提交标题和图谱，失去左右对照关系。

**图谱继续锚定按钮向上展开**：新会话的输入框在页面中间，上方空间不足，图谱会贴近顶部且列表高度受限，采用视口居中布局。

**仅按视口居中和限高**：浏览器高度缩小时，视口居中的浮层仍会覆盖底部输入框。输入区可见性优先于图谱高度，增加卡片顶部边界约束；新会话上方空间较小时接受缩短列表，通过内部滚动浏览。

**一次读取全部历史和所有文件详情**：大仓库打开成本随历史长度增长，且多数提交不会被查看。改为分页历史、按选择读取详情，并压缩文件摘要。

## Consequences

用户能在当前会话内查看真实提交背景与合并关系，长正文不会撑满浮层，浏览操作不会意外检出。Git 与图谱布局有独立测试，并在 `dsh web` 中验证实际组件。

历史搜索只覆盖已加载的提交字段，不扫描所有提交正文；可继续加载或刷新。所有已加载行仍由 React 渲染，极长会话历史尚未虚拟化；高并行分支可能占用较宽的图谱列。Git 输出沿用现有执行器的缓冲与超时上限，超大正文或文件统计可能失败并提供重试；此版本不展示补丁和完整文件清单。
