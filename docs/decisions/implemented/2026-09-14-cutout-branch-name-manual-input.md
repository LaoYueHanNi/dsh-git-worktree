# DR: 切出弹窗的新分支名由用户手动输入，不再自动预填

Status: implemented

## Problem

切出弹窗（勾选工作树开关、右键「新建分支并创建工作树」、worktree 模式选中当前分支三条路径共用）一直把新分支名**预填**为第一个空闲的 `<基准>-wt`（见 [勾选工作树即弹切出确认](2026-08-29-worktree-cutout-from-current-branch.md) 的 2026-08-30 修订）。预填让"确认"变成一步——但用户实际经常不满意 `-wt` 命名：要么确认前手工改，要么事后去终端 `git branch -m`。更重要的是预填**弱化了"这是在命名一个新分支"的意识**： `-wt` 后缀是插件的命名约定，不是用户的命名决策，自动生成的名字悄无声息地落进分支表和磁盘目录名。新分支名应当像创建分支弹窗一样由用户亲手输入。

## Decision

切出弹窗的新分支名输入框**初始为空**，用户必须亲手输入：

- 三条切出路径（右键「新建分支并创建工作树」、worktree 模式选中当前分支——勾选开关当日稍后整体移除，见 [移除工作树勾选开关](2026-09-14-worktree-toggle-removed.md)）统一不再预填，`ConfirmState.draft` 留空。
- 输入框 placeholder「新分支名称」，打开即自动聚焦；确认按钮在草稿通过 git ref-name 校验且不与现有本地分支重名前**保持禁用**——空名字天然禁用，无需额外状态。ask 行随之改为通用的「输入新分支名称」（与创建弹窗同款）：要输入的正是名字，基准语境由"刚右键的那一行"承载。
- 命名空间校验不变：与创建/重命名弹窗同款（`branchNameIssue` + 查重），自己排除自己的规则不适用（初始为空）。
- host 端 `cutoutBranchName` 的 `-wt` 后缀巡检**保留**：它服务于"显式名字缺省"的 API 形态（旧客户端/直接调路由），UI 层不再触达。

## Alternatives considered

- **保留预填、仅改 ask 文案提示可编辑**——零成本，但预填本身就在对抗"用户命名"的意图：文案劝不动一个已经填好的输入框。放弃。
- **预填改为聚焦全选**（打开即选中预填文本，打字即覆盖）——键盘用户体验好，但"输入框里已经有名字"的视觉暗示仍在，且全选态在鼠标用户点入后丢失，两种进入方式行为分叉。放弃。
- **保留预填但仅在右键路径、勾选路径维持**——两条路径是同一个弹窗组件，分叉只会让"为什么这里要我自己打字、那里不用"成为新的疑惑。统一为手动输入。

## Consequences

- 得：新分支名回归为用户的显式命名决策，`-wt` 不再未经思考地落进分支表与磁盘目录；与创建分支弹窗的输入心智一致（空框 + 校验 + 禁用确认）。
- 代价：多打一次字（高频路径上一致性换便捷）；`firstFreeCutoutName` 客户端函数删除，host 端 `cutoutBranchName` 成为仅 API 兜底的代码。
- 边界：用户输入 `%BASE%-wt` 之外的名字完全自由，插件不再对命名模式有任何倾向；输入与现有分支重名时确认禁用并红字提示（与创建弹窗同文案）。
