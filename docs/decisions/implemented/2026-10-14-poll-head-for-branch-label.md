# DR: 底部分支标签定时读 HEAD，跟上外部签出

Status: implemented

## Problem

在终端、本窗口里的会话，或其他 Git 工具里切换分支之后，底部显示当前分支名的标签仍停在旧名字。标签只在挂载、目录变化、插件自己做完操作、窗口重新获得焦点、页面从隐藏变为可见，以及点开分支列表时才重新请求。同窗口里切分支不会让窗口失焦，页面也没有从隐藏变成可见，于是标签一直旧着，直到用户点开列表。

## Decision

页面可见、并且已挂载的会话标签上已经有分支名时，每 5 秒读一次当前签出的分支。侧边栏仅列出目录不会订阅轮询。读的是 HEAD 文件，不起 git 进程。名字和标签上的不同，并且当时没有插件自己的操作在进行，才走原来的完整状态刷新。同一目录上的多个标签合并成一次读取。页面隐藏时不读。窗口重新获得焦点、页面重新可见、点开列表这三次立即刷新保留。

间隔从 2 秒调整为 5 秒，每个订阅目录的常态请求量从每分钟 30 次降到 12 次；保留几秒内跟上外部签出的体验，不采用最多等待约 10 秒的间隔。

读取从会话目录向上找 `.git`。`.git` 是目录就读里面的 `HEAD`；是文件就按 `gitdir:` 指到的位置读（相对路径按该文件所在目录解析，只跟一跳）。`ref: refs/heads/<name>` 是该分支；一行提交号，或指向 `refs/heads/` 以外的符号引用，记为 `HEAD`（与 `git branch --show-current` 空输出时标签上的字一致）。文件缺失、半截、或超长，这一拍回答 `pending`，标签保持原样。目录不在任何仓库里回答 `repo: false`，轮询不因此清空标签。

接口是 `GET /plugin/git-worktree/head?path=`。还没显示出分支名的会话（加载中，或不是 git 目录）不参加轮询。一次完整状态请求和另一次重叠时，后发出的结果才写上标签。

完整状态刷新遇到网络或 HTTP 错误时保留同一目录最后一次成功的状态，不取消 HEAD 订阅；下一拍仍发现分支不同就再次刷新。成功回答 `repo: false` 才清空标签，切换会话目录仍先清空旧目录状态，不借用旧标签。

每个目录独立限制为一个在途 HEAD 请求，不等待其他目录完成。单次请求 5 秒超时，通过 `AbortSignal` 中止；轮询也等待取消信号，以免未响应取消的请求一直占住该目录。页面隐藏或目录最后一个订阅退出时取消在途请求，迟到结果不通知标签。重新可见或重新订阅后可以继续读取。

## Alternatives considered

- **每 3–5 秒拉完整 `/status`** —— 一次状态要多条 git，其中领先/落后随分支数变重。标签过期的只是当前分支名。放弃。
- **每 2 秒执行 `git branch --show-current`** —— 语义和现在的标签一致，但 Windows 上主要开销是启动进程（一次大约几十毫秒），而 HEAD 只是一个几十字节的文件。放弃。
- **常驻一个 git 或 shell 进程反复问** —— git 没有「进程不退出、反复回答当前分支」的接口；留一个 shell 再喂命令，要自己管目录、超时和崩溃重启。宿主进程已经常驻，直接读文件即可。放弃。
- **监听 HEAD 所在目录，再用推送通知页面** —— 签出时 git 用改名替换 HEAD，Windows 上盯着文件本身会在替换后失效；还要一条推送通道和断线重连。同类的推送在[同步远程分支](./2026-08-30-fetch-sync-remote.md)里因另一理由否过；这次 HEAD 确实会在本地变，但每 5 秒的文件读取已经够用，不把那条通道加回来。
- **挂上 DSH 命令结束再刷新** —— 盖不住外部终端和其他 Git 工具。放弃。

## Consequences

- 代价：多一条只读查询；会话标签已经显示且页面可见时，每个订阅目录大约每 5 秒读一次小文件；分支真的变了才打完整状态。正常情况下标签最多晚大约 5 秒；失败或超时会延后，保留旧标签并重试。
- 换来：同窗口终端、分屏且窗口不丢焦点时，底部的分支名会自己跟上，不必先点开列表。
- 边界：外面新建了一条还没签出的分支，HEAD 不变，这次读取不会发现，点开列表时的全量刷新仍负责列表。`GIT_DIR` 不参与文件查找；若它和目录不一致，以完整状态（走 git）写上标签的结果为准。读失败不改标签。
