# DR: 更新当前分支（fetch + --ff-only 快进）

Status: implemented

## Problem

提取（fetch）只更新远程跟踪引用，本地分支停在原地；要让当前分支吃到远程新提交，用户仍需去终端或 IDEA 做 pull/merge。IDEA 的"更新所选"日志证实其为多步组合：`fetch origin --prune` → `merge origin/<branch>`——这不是一条命令，设计时必须想清楚每一步的失败面。

## Decision

> [!NOTE]
> 本决策中“为更新入口不扩展 upstream 契约”的范围已于 2026-10-15 由 [DR: 分支显式推送、首次发布确认与 IDEA 同步箭头](2026-10-15-branch-push-and-colored-tracking.md) 扩展：首次发布需要 upstream 字段，当前行右键据此提供更新；工具条仍保留原有行为。

> [!NOTE]
> 本决策中更新的“fetch 最多 20 秒”与“执行中箭头透明度脉冲”的反馈形态已于 2026-10-16 由 [DR: 提取与更新的实时进度：流式路由、逐远程拉取与悬浮进度卡片](2026-10-16-fetch-update-live-progress.md) 取代：更新改为流式应答，拉取阶段显示可取消的悬浮进度卡片，快进阶段不可取消。两步顺序与 `--ff-only` 仍然有效。路由仍把 git 原文放进 400；toast 对分叉、脏工作区、无上游各给一句下一步，见下方前端反馈。

工具条新增实线左下箭头（位于定位与虚线提取之间——虚线/实线成对：虚线只搬元数据，实线会动本地分支），对应 `POST /plugin/git-worktree/update`：

- **服务端一个路由顺序两步**：`fetchAll`（复用提取的原语）→ `git merge --ff-only @{u}`（在会话目录自身 toplevel 执行，linked worktree 更新自己持有的分支）。是否真的移动了 HEAD 由前后 `rev-parse HEAD` 比较——比解析 merge 输出文案可靠（git 消息可能本地化）；`branch --show-current` 回显分支名。
- **范围只限当前检出分支**：菜单是单 worktree 语境，其它未检出分支没有"就地更新"的语义。
- **失败面如实暴露、绝不代劳**：`--ff-only` 遇到本地分叉提交直接拒绝（`Not possible to fast-forward` 转 400）；无上游 / detached HEAD 同为 400；工作区未提交改动由 git 自己拒绝——**不自动 stash**（写用户工作区的操作插件不代劳）；不做 rebase 模式（写历史）。
- **前端反馈**：执行中实线箭头透明度脉冲（箭头是方向性图形，圆形刷新语言的旋转读作乱转）；成功 toast 区分"已快进到远程最新"与"已是最新"；菜单保持打开并原地刷新。单飞与提取/确认共享 `busyRef` 互斥。失败 toast 对得上原因：分叉说「分支已分叉，请先合并或变基上游」，脏工作区说「先提交或暂存」，无上游说「先推送并设置上游」。路由仍回 git 原文；未识别的失败去掉命令行和 `hint:` 行后再放进「Git 工作树：」。不提示「再更新一次」来对付分叉——更新就是刚刚失败的那一步。

## Alternatives considered

- **复用提取按钮合并两步**（fetch+ff 一键）——提取是无前置条件的元数据操作、更新要求上游且会动本地分支，合并后"只想看看远程有什么"的轻动作也变得有副作用。放弃，虚线/实线两键成对，视觉语言同 IDEA。
- **rebase 模式**（IDEA 的可选项）——写历史，分叉提交被改写，风险远超本插件"分支可见性 + worktree 隔离"的职责。放弃，`--ff-only` 拒绝即保护。
- **自动 stash 未提交改动**（IDEA 行为）——stash/pop 失败时现场恢复复杂，且用户可能根本不想动那些改动。放弃，git 自然拒绝 + toast 指路。
- **两步拆两个路由**（前端串行调用）——中间态暴露给前端（fetch 成功 merge 失败时前端要拼装错误），服务端单路由顺序执行更原子。放弃。
- **无上游时预判禁用按钮**——需要扩展 /status 契约携带 upstream 信息，为一个边缘态扩全量类型不划算；失败 toast 已足够指路。放弃，后续真有需要再扩。

## Consequences

- 代价：工具条增至 5 枚；update 是最长的复合操作（fetch 最多 20s + 三条本地命令），期间其它动作因单飞被挡。
- 换来："吃远程新提交"闭环不出 Web UI。分叉、无上游、脏工作区各有一句下一步，不再把 git 的 `hint:` 建议铺满 toast；插件仍绝不越权改写用户历史或现场。
- 边界：`@{u}` 依赖分支的上游配置——新建分支若未 `git push -u`，更新会报无上游（400 提示）；这符合 git 语义而非插件缺陷。
