# DR: 紧凑推送审阅窗口

Status: implemented

## Problem

用户通过 IDEA 截图及本地 HTML demo 确认：右键“推送”需要先展示来源、目标和待推送提交，支持新建远程分支、选择远程、标记和强制推送。原来的单远程确认、多远程选择即推送缺少提交审阅，不符合最终交互。布局必须紧凑，复用 DSH 原生样式，不能展示文件详情或过宽的双栏。

## Decision

> [!NOTE]
> 本决策中“推送期间窗口保持打开并禁用、成功后才关闭窗口、失败只留错误”的执行流程已于 2026-10-16 由 [DR: 推送的悬浮进度](2026-10-16-push-floating-progress.md) 取代：点“推送”后窗口立即关闭，进度走悬浮卡片，失败时窗口带原因与原选择弹回（失败后重读远程预览、本地快照沿用、错误分类与展示仍按下文）。120 秒推送超时一并改为 5 分钟无输出才终止。

部分取代[分支显式推送与同步箭头](2026-10-15-branch-push-and-colored-tracking.md)中的推送交互与无标记、无强制推送限制，保留显式来源、默认同名目标、默认 remote 优先级及同步箭头。

- `PushDialog` 使用 DSH `Modal` 与 `Menu`，宽 420px、受视口约束。顶部显示来源 → 远程 : 目标；仅多个 remote 时出现选择菜单，不提供“定义远程”。目标名称点击编辑，Enter 校验并应用后关闭编辑小窗；阻止 Enter 默认动作，避免焦点回到触发按钮后再次打开。中文输入法组合期的 Enter 不提交。名称不合法时输入框标记 `aria-invalid`；重新选择相同的远程或应用相同的名称不算变更，不会触发新的远程校验。
- 目标编辑小窗只在 Enter 应用、Esc 放弃或点击小窗右上角 × 时关闭，点击窗口其他位置不会关闭它，避免失焦误触丢掉刚输入的名称；Esc 在捕获阶段只关闭小窗，不连带关闭推送窗口。
- 推送窗口本身也不因点击遮罩而关闭：宿主 `Modal` 的遮罩点击与 Esc 走同一个关闭回调，一次误点就会丢掉目标、预览与编辑。窗口在 `window` 捕获阶段只拦截目标恰为遮罩（对话卡片的前一个兄弟元素）的点击；Esc、右上 ×、取消照常关闭。宿主若改变遮罩的标记结构，拦截落空，遮罩点击恢复宿主默认行为，不会误伤其他点击。
- 目标编辑小窗相对目标分支名称左边缘定位，位于名称正下方，挂载后测量，右侧放不下时改与名称右缘对齐；背景使用 DSH 不透明的 `--dsw-alias-bg-layer-2`，保留原生边框、圆角和阴影，避免半透明菜单色让下方提交消息透出。来源分支名最多占映射行的一半，保证目标名仍可见。
- 提交数量和底部操作固定，提交第一行消息列表独立滚动，最多约六行高。长消息单行省略并通过标题查看完整内容，不显示哈希、正文或文件面板。空的新远程分支仍可推送；已有目标且没有新提交时禁用普通推送，勾选标记仍可执行。列表最多返回 200 条，保留真实总数及截断提示。
- 打开窗口直接复用分支列表已有的 upstream 和领先数，在目标规划及提交消息读取期间显示数量，不为此重新刷新分支状态。规划完成前明确写“领先上游”；之后仅当所选 remote/target 与有效 upstream 完全一致时作为暂定提交数，切换远程或异名目标立即停止复用。无 upstream、upstream 已消失、分支不匹配时不复用；提交列表到达后以对应快照替换，计数本身不启用推送。读取提交消息时最多取 201 条作为截断探针，200 条及以内直接使用列表长度，只有超过上限才额外计算真实总数。提交数量与领先数文案区分单复数（`pushCommitCount.one/.other`、`aheadTitle.one/.other`）。
- `/push-plan` 解析本地 remote 配置与默认目标，并附带该默认目标的本地快照（`local`，语义同下文 `localOnly`：只读本地 tracking ref 与提交，仅供展示；构建失败则省略，不影响规划）。客户端用它渲染首屏，不再为默认目标单独发起一次 `localOnly` 预览；换到其他远程或目标时才再请求本地与远程两类预览。新增 `/push-preview` 接受显式 remote、target，验证配置后通过 Git `remote get-url --push` 与 `ls-remote` 读取实际推送目的地；目标不存在显示“新建”。一个 remote 配有多个 push URL 时拒绝预览，而不是把一个目标窗口用于多个不同仓库。若远端目标对象在本地缺失，按目标 ref fetch 对象，使用空 refmap、`--no-write-fetch-head --no-tags --no-recurse-submodules --no-auto-maintenance`，不改 HEAD、工作区或 tracking refs。
- `/push-preview` 支持 `localOnly: true`，只读取所选 remote/target 的本地 tracking ref 和提交，不执行远程查询或 fetch。客户端并行请求本地预览和远程校验，先显示可用的本地提交并标注“本地预览 · 正在校验远程…”，校验失败保留列表和错误。远程结果始终优先，迟到的本地结果不能覆盖；切目标、刷新或关闭后丢弃旧请求结果。tracking refs 可能过时、缺失，或来自不同 fetch URL，因此本地结果不显示“新建”，不启用普通或强制推送；实际校验结果到达后才替换列表、启用相应操作。显式目标预览不重复解析默认推送配置，互不依赖的本地 Git 读取并行执行。读取尽量合并：推送 remote 配置只用一次 `git config --get-regexp`（仅 `remote.pushDefault` 与 `branch.*.pushRemote`，分支名按原大小写匹配，同键后者优先），规划时分支事实、remote 列表与配置三路并行；来源 OID 与跟踪事实来自同一次 `for-each-ref`，同时供提交前的陈旧检查使用，不再单独 `rev-parse`；`remote get-url --push --all` 兼作 remote 存在性检查；缺失对象探测（`cat-file`）只在提交遍历失败后才执行。`ls-remote` 超时为 20 秒，按需获取对象仍允许 120 秒。
- 已有目标用源提交减去实际远端目标历史计算列表；新建目标则排除本地已知的所选 remote 其他分支历史，因此零新提交也能新建远端引用。新建目标的历史去重依赖本地 remote-tracking refs，未获取的其他分支可能使列表多显示历史提交，但推送仍是所选源引用与目标。
- 标记默认不推送。勾选后的“所有”对应 `--tags`，包括与当前分支无关的本地标记；“跟随提交”对应 `--follow-tags`，只补齐远端缺少、且指向推送历史的附注标记，不含轻量标记。触发按钮与选项标题说明语义；默认 `--no-follow-tags` 抑制环境配置的隐式扩张。强制选项只针对目标分支，不强制覆盖标记冲突。
- 普通按钮仍叫“推送”，下拉只有“强制推送”，点击直接执行，不增加模式选择或额外确认。后端使用 `--force-with-lease=refs/heads/<target>:<预览 OID>`；目标原先不存在时使用空 OID lease。拒绝无显式目标、无完整源 OID或无目标 lease 的强制调用。提交前校验源分支仍等于预览 OID，变化则要求刷新；普通推送继续禁用 force。
- 发布（显式 remote 与 target）仅在分支没有 upstream、upstream 已消失，或现有 upstream 不是同名分支（如从 `origin/main` 继承）时追加 `--set-upstream`。已有同名对应分支时（可能位于另一个 remote，如 fork 工作流里的 `remote.pushDefault`），一次性推送到别的 remote 或异名目标不改写其 tracking。
- 预览变化立即使旧数据不可提交，异步结果按目标和生命周期隔离；菜单选择不执行 push。推送失败后保留提交列表与错误，并重新读取远程预览（本地快照沿用；认证类失败不重读，结果不会变）：被拒绝通常正因远端在预览之后前进，旧的源 OID 与 lease 再试必败，重读后重试才基于当前事实。常见原因由 `classifyPushFailure` 识别（需先同步 / 非快进、force-with-lease 过期、本地 pre-push 钩子、远端拒绝或受保护分支、认证），显示一行本地化说明。“落后”和“预览过期”只靠这一句就说清了原因和下一步，Git 的 `hint: … git pull …` 只是样板文字，不再展示；“远端拒绝”“本地钩子”和“认证”保留 Git 自己的那句原因，因为里面有具体的规则、钩子或主机名（去掉 `git … failed (exit N):` 命令行前缀，以及在还有别的行时的 `error: failed to push some refs` 套话，免得它们把真正原因挤出短滚动框）；未识别的失败同样去掉命令行前缀，其余原文保留。本地 pre-push 钩子不归入“远端拒绝”。错误留在窗口，提供刷新预览和重试；执行期间禁用目标修改、关闭和重复提交，并复用父组件的 fetch/update 单飞锁。切换会话目录时卸载窗口，旧结果不回填新仓库。成功刷新状态、关闭窗口并显示来源和目标。

## Alternatives considered

- **继续小浮层确认或选择远程即推送** —— 用户明确拒绝，并通过可交互 demo 确认需要独立推送审阅窗口。
- **复制 IDEA 的宽双栏与文件详情** —— 用户只需要提交消息第一行，420px 单栏及独立滚动列表能保留审阅功能并减少遮挡。
- **只依赖本地 tracking OID 判断已有目标** —— 容易把远端存在但尚未 fetch 的分支标成新建；显式读取推送 URL 的目标同时为强制推送提供可靠 lease。
- **等远程校验结束才展示提交** —— SSH 连接、认证或按需 fetch 会让整个提交区域空等；本地快照可先支持审阅，保留校验期间禁用推送的约束即可避免把缓存当作远端事实。
- **裸 `--force` 或不带期望 OID 的 force-with-lease** —— 后者依赖可能被后台 fetch 改变的 tracking refs，二者都不能保证不覆盖预览后新出现的提交；采用显式 OID lease。
- **点击窗口别处关闭目标编辑小窗，或点击遮罩关闭推送窗口** —— 用户明确要求小窗只通过 × 关闭；两处承载的输入与审阅进度都有成本，失焦即丢过于脆弱。代价是遮罩拦截依赖宿主 `Modal` 的标记结构，已设计为失效时退回宿主行为。
- **强制推送前再确认一次** —— 用户明确表示选择“强制推送”即代表认可，lease 已拦下预览之后的远端更新；不增加确认步骤。
- **发布时总是 `--set-upstream`** —— 会把 fork 工作流里已有的同名上游悄悄改指向个人 remote，也会让一次性的异名推送改写 tracking；只在分支没有真实对应分支时采用。
- **失败后只显示错误，由用户手动刷新** —— 拒绝多半因为预览已过期，不重读则按钮仍用旧 OID 重试，必然再败。
- **规划与首屏本地预览各发一次请求** —— 多一次往返并重复读取同一批本地引用；规划响应附带快照即可。
- **自动 fetch 整个 remote 或建立新进度通道** —— 当前窗口只需目标历史，按需获取缺失对象并保留执行中状态足以覆盖范围，避免额外全量网络操作与流式协议。

## Consequences

获得与已确认 demo 一致的紧凑审阅流程，以及可选择的标记推送和受 lease 保护的强制推送。本地提交展示不等待网络，远程校验后列表可能改变，额外的本地请求增加少量进程开销。离线或认证错误时无法确认真实目的地，窗口保留本地预览和错误并允许切换远程或刷新，但不允许推送。Git push 的多引用更新不保证原子性，部分标记被拒绝时 Git 可能已更新分支；因此失败后仍刷新状态，重试前可刷新预览。live 推送不再用 120 秒总超时，其进度与空闲终止见悬浮进度决策；不带 live 的直接调用仍是 120 秒，到点仍不能证明远端没有收到。

复用领先数让已有状态立即可见，但它只是本地 upstream 快照，不能代表其他推送目的地或实时远端。测试覆盖无额外状态请求的事实传递、规划和消息请求未完成时即显示计数、无效 tracking 信息与异名默认目标不复用、切换远程或目标立即撤下缓存计数、远程结果替换旧计数，以及 0、2、200 条完整列表不再调用计数命令、超过 200 条仍返回真实总数。

验证包括真实临时本地 bare 仓库中的离线本地预览（禁止任何网络命令、精确匹配 tracking ref）、空分支发布、第一行提交列表、异名目标比较、独立 push URL、缺失对象获取且不移动 tracking refs、源分支变化拒绝、并发远端更新的 lease 拒绝、显式强制更新和三种标记范围；控制器测试覆盖慢网络期间本地列表可见且普通/强制推送均不可执行、校验失败保留本地列表、远程结果优先于迟到本地结果、切换目标丢弃两类旧结果、本地失败不阻断远程成功、Enter 关闭编辑器、重复提交、失败重试与切目录关闭。外部 GitHub/Gitee 认证与宿主实际窗口联调需要加载本次构建后的 DSH。

后续补充的测试覆盖：规划响应附带本地快照时首屏不再单独请求、换目标后两类预览重新读取；相同远程或名称不触发重新校验；目标编辑小窗在外部交互下保持打开、仅 ×、Enter、Esc 关闭并丢弃未应用输入；遮罩拦截只吞目标为遮罩的点击（含标记缺失、未挂载等落空情形）；失败后重读且保留本地列表，认证失败不重读，已识别原因附说明（落后/过期不展示 Git 原文，拒绝类保留）、未识别原文照常、换目的地清除旧错误；单复数文案；推送失败原因分类的各标记与优先级，以及去掉命令行前缀后的 Git 输出。服务端覆盖规划只发三路读取且一次 config、`--set-upstream` 的五种取舍（含 fork 同名对应分支不被改写）、规划附带快照与快照失败时保留规划、预览只发最少 Git 调用及缺失对象的 fetch 重试；真实 bare 仓库验证混合大小写分支的 `pushRemote` 读取、fork 式同名上游保持不变，以及发布后继承的 `origin/main` 上游被替换。
