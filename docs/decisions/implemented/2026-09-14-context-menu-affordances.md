# DR: 右键成为唯一鼠标通道后的三项补齐，与提示文案的信息层裁剪

Status: implemented

## Problem

[分支行右键菜单](2026-09-13-branch-row-context-menu.md)把双击整体移除，右键菜单成了鼠标执行行级动作的**唯一**通道。唯一通道的门槛不是"能点"，是"点之前知道点的是谁、不用鼠标也能点、页面动了不会点错"——初版三项都欠着：菜单被 clamp 到视口边缘时会脱离触发它的那一行，而菜单自己不说目标（六个动词里有"删除分支"）；菜单打开后没有任何键盘路径；滚轮滚动不产生 pointerdown，菜单会悬在原位而锚定行已经滑走，此时点"删除分支"删的是一个用户以为在别处的分支。

同一批 UI 里还积了一层反向问题：提示文案在解释**实现**而不是**后果**（"DSH 尚未开放多工作区聚合接口"），几处 hint 长到 90 字以上，用户要读完两行半才知道开关干什么。

## Decision

**三项补齐（全部落在 `BranchMenu.tsx` 的 `ctxCard`）**

- **目标行标题**：菜单顶部一行 `.ctxHeader` 显示右键的那一行名（secondary 色、12px、超长省略、`title` 带全名）。它是菜单里**唯一**允许撞到 280px 宽度上限的一行——动词标签是固定文案，只有这行装分支名。不做成菜单项（无 hover、无焦点），它是标签不是第七个动词。
- **键盘可达**：菜单打开后 rAF 聚焦第一项（与浮层同款姿势：首帧是隐藏的测量布局，`focus()` 打在 `visibility:hidden` 上无效），`ctxCard` 挂 `onKeyDown` 处理上下键（两端循环）、Home/End，Enter 交给 button 自身的激活。项目集合**从 DOM 读**而非从 `ctxItems` 索引——聚焦项本身就是唯一真相，不引入会漂移的索引 state。Escape 刻意**不**在这里处理：document 监听器已把菜单排在浮层之前的第一档，撤销顺序只应有一处定义。菜单 portal 在 body、不在 `cardRef` 内，而 document 的方向键处理以 `card.contains(activeElement)` 为门槛，天然不冲突。
- **滚动/缩放即关闭，而不是重新定位**：卡片与三个浮层都是 resize/scroll 时**重新放置**，菜单相反——它锚的是一个光标点，点一旦移动就不再是用户瞄准的那个点。加 `resize` 与 **capture 相的** `scroll` 监听（列表在卡片内滚动，scroll 事件不冒泡到 window），触发即 `setCtx(null)`。

**动作自述基点**

右键某行新建，浮层此前只说「输入新分支名称」——菜单已被浮层替换、被 clamp 时原本就没贴着行，"从哪切"完全不可见。两处补基点：创建浮层的 ask 在有基点时用 `createFlyAskFrom`（`从 {branch} 新建分支`），剪出工作树的 ask 用 `cutoutFlyAsk`（`从 {branch} 切出新分支并创建工作树`）。基点名走 `remoteNameMap` 的**逆映射**显示：state 里存的是动作名（`origin/feat/x`，`git branch` 需要它），单 remote 下用户只见过 `feat/x`，不能突然拿动作名回敬他。确认按钮 `createCheckoutConfirm` 由「检出」改为「新建并检出」——它做两件事，按钮上只写一件是在藏动作。

**其余交互**

- 展开/折叠工具按钮在搜索态 `disabled`：搜索视图是强制展开的扁平列表，没有文件夹可折，点了只会改一份看不见的状态，然后在清空搜索时突然生效。
- 清理记录脱离 `autoPruneWorktrees` 开关，改为「有记录就显示」——刚关掉自动清理正是最想查它干过什么的时刻。默认只显示最近 3 条，其余折在「展开全部 {n} 条」后（日志上限 20 条，设置卡片不是日志页）；记录行的 `repoName`/`branch` 缺失时不再渲染孤零零的 ` /`。
- `BranchChip` 的 toast 由单值 state 改为队列（`pushToast` 入队、`onDone` 出队、渲染队首）。一条流程能连发两条——工作树创建的 fetch 警告，紧接着自动清理的战报——单槽位让第二条在第一条被读到之前就把它抹了。
- 管理弹窗的计数区分有效与无法识别（`manager.countOrphans`）：无法识别的目录自成一组挂在列表尾部，标题只报有效数时，四个分组顶着「3 个工作树」读起来像算错了。

**文案裁剪原则：说后果，不说实现**

`cardGroupSidebarHint` 与 `cardGroupSidebarNote` 合成一句，删掉「DSH 尚未开放多工作区聚合接口」「官方接口一旦开放会第一时间改用原生实现」——这是给维护者看的路线图，用户要的是"这开关干什么、出事怎么退"。`cardAutoPruneHint` 从 97 字压到 45 字（"惰性检查一次""按最近使用时间从最不活跃的开始"都是机制，留"超出就删最久未用的"这个后果）。`worktreePurge.desc` 去掉「多半是某次删除被文件占用中断后的残留」——对着不可恢复的删除做成因推测，既不保真也不帮决策。`cardManageHint` 删「删除与侧栏的删除工作树走同一流程」（实现一致性，不是用户关心的）。`pruneFailed` 去掉「可在设置中打开管理查看」（toast 可能就在设置页内触发）。反向补一处：`deleteBranchAsk` 加「未合并的分支会被拒绝」——菜单只提供安全 `-d`，这是**降低**用户心理成本的信息，与压缩不矛盾。

同时删除 5 个无引用的 key（`manager.colRepo`/`colBranch`/`colActivity`/`unknown`/`removeFailed`）——表头方案改成分组头后就没人引用了。

## Alternatives considered

- **完整 roving tabindex**（菜单项只有一个进 tab 序，其余 `tabindex=-1`）——是 WAI-ARIA menu 的标准姿势，但本菜单是个转瞬即逝的光标锚定层，打开即聚焦、Escape 即关闭，不存在"tab 进入/离开"的场景；维护每项的 tabindex 只会多一份要与 `ctxItems` 同步的状态。放弃，用「打开聚焦首项 + 方向键循环」这个够用的子集。
- **保留双击作为鼠标快速路径**——本可以让"通道唯一性"的三项补齐不那么紧迫，但双击的可发现性短板与动作扩展性问题原样还在（前一条 DR 已裁决），为了省这三项而留一条冗余通道是本末倒置。放弃。
- **滚动时重新定位菜单（跟随锚定行）**——需要把菜单从"光标点锚定"改成"行元素锚定"，而光标锚定正是它零位移的来源（二级弹窗就地替换菜单也依赖这个点）。放弃，滚动即关闭：代价是滚动中断操作，收益是永不指向错的行。
- **toast 改为多条同时堆叠**——队列已经解决了"被覆盖"，同屏多条要额外处理堆叠位置与总高度上限，而这里的并发量级是 2。放弃，串行足够。
- **清理记录做成独立弹窗**——记录是低频查阅物，独占一个弹窗的入口成本高于折叠列表。放弃，默认 3 条 + 展开。

## Consequences

- 得：右键菜单三项门槛齐了——目标可见、键盘可达、页面一动就撤；新建/剪出不再是"名字对了但不知道从哪切"；文案按"后果优先"收紧后，三处开关的说明都落在一行内；死 key 清零。
- 代价：菜单多一行标题（六项菜单高度 +20px 左右）与两个监听器（随 `ctx` 生灭）；`createFlyAskFrom`/`cutoutFlyAsk`/`manager.countOrphans`/`cardPruneHistoryMore`/`Less`/`cardSwitchFailed`/`manager.truncated` 共 7 个新 key，中英各一份；toast 队列让失败信息可能延后一个显示周期才出现（原先是立刻覆盖）。
- 边界：`:focus-visible` 意味着鼠标右键打开时首项不显示高亮（编程聚焦沿用上一次输入模态），只有按下方向键后才可见——这是刻意的，鼠标用户不受打扰；滚动关闭对**触控板惯性滚动**同样生效，轻微误触会关掉菜单；清理记录的展开状态每次展开卡片都重置为折叠；`manager.countOrphans` 以逗号起头拼在 `manager.count` 之后，属于句子级拼接（两种语言都成立，第三种语言接入时需重新裁剪）。
