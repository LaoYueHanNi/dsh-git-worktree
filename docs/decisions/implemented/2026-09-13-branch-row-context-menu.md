# DR: 分支行右键菜单——六动词行级通道，取代双击与工具条加号

Status: implemented

## Problem

分支菜单的行动作只有一条触发通道：单击选中 + 双击/Enter 执行（IDEA 模型）。双击作为鼠标快速路径有结构性短板：可发现性差（没有任何视觉线索提示"还能双击"），且没有扩展空间——行级动作（复制分支名、复制工作树路径、从任意分支新建、删除分支等）无处安放，往双击上继续叠语义只会加重误触。需要一条新的触发通道承载行级动作；通道落定后，双击与只认"当前分支"的工具条加号的存废也要一并裁决，不能留下冗余的执行路径。

## Decision

分支行（树形叶子、工作树扁平行、搜索命中行三种形态）新增 `onContextMenu`：弹出**光标锚定**的行级菜单（`.ctxCard`，一层 portal）。分支行给**六动词全集**，每个动词在无对象处退化：

- **签出**：本地与远程统一为一个动词（远程走 dwim 检出孪生），汇入现有 `pick` 通道但**免确认直接执行**——`git switch` 是可逆操作（失败即原地不动），确认弹层在这里是伪安全（与工作树跳转同一逻辑）；当前分支行无此动词（无可签出）。worktree 模式例外：此时"签出"的真实意图是进 worktree，仍走带文案的 worktree 确认弹层（reuse 或 cutout）。
- **新建 / 新建并检出**：打开同一个创建弹窗，起点是右键的行（远程行交出真实 `origin/x` 动作名，走 pick 同款显示名映射）。`POST /branch` 的可选 `from` 键承载起点，`checkout` 布尔拆分两档：**新建** = `git branch <name> <from>`，不碰任何检出——朝别的分支去的创建不许悄悄挪当前会话的 HEAD；**新建并检出** = `git switch -c <name> <from>`，建完当场签出（一把执行，免二次确认），确认按钮随之显示「检出」。弹窗文案统一为「输入新分支名称」——起点信息由"刚右键的那一行"承载，不再复述在标题里。两者受 `canCreate` 闸门约束（worktree 模式与 linked-worktree 会话不出现）。
- **二级弹窗就地展开**：从菜单项打开的二级弹窗（创建/重命名/删除确认，以及 worktree 模式下的签出弹层）直接出现在**一级菜单位置**（`ctxPointRef` 记录菜单打开时的光标点），替换菜单原位——光标不动，二次点击/输入零位移；`measure-then-place` 后钳回视口内。带输入的弹窗（创建/重命名）打开即自动聚焦输入框——聚焦必须走 rAF（首帧是隐藏的测量布局，`focus()` 打在 `visibility:hidden` 上是无操作，与确认按钮同款姿势）。非菜单路径（Enter、确认中再点行）发起的弹层维持卡片右侧的既有姿势。
- **一级菜单贴内容**：`.ctxCard` 宽度 `max-content`（无固定/最小宽度，仅 280px 上限兜底）——启动器紧凑比拉伸好看，宽度即最宽项加内边距。
- **重命名分支**：仅本地行（远程分支不归我们管），打开**重命名弹窗**（创建弹窗同款姿势：卡片右侧、输入预填当前名、实时校验、一把执行）——`POST /branch-rename` 新路由跑 `git branch -m`（refs 全仓共享，指向旧名的 worktree HEAD 随引用走；git 拒绝重名目标，400 回包，弹窗保留改名重试）。命名空间规则与创建共用：ref-name 校验 + 查重，自身原名排除、未改动时确认禁用。
- **删除分支**：仅本地行且非当前行（git 拒绝删当前检出分支，条目只会是死胡同）。走**安全 `-d` 形态**——git 拒绝未合并提交与被任何 worktree 占用的分支，全部 400 toast 回包；**刻意不提供 `-D` 强删**，菜单点击永不丢弃提交（刻意强删是终端的事）。二次确认复用确认弹层（锚在那一行旁），确认后 `POST /branch-delete` 删除、列表原地刷新、菜单保留。
- **复制分支 / 复制路径**：分支行复制显示名、工作树行复制目录路径（所见即所复制；单远程下显示名已去前缀，复制跟随显示形态）。走基础库 `writeClipboard`（含 `execCommand` 回退），成功后 `Toast` 显示共享的 `hover.copied` 文案。
- **工作树行不进动词集**：它的职责是跳转，保留两项目（"跳到此工作树"走 `pick` 免确认直跳 + "复制路径"）；其分支必然已被别处检出，签出/新建并检出/删除落在它身上都是语义噪音。
- **工作树动词按未开始会话并入**：初版把两个工作树动词做成"勾选开关打开时的菜单换脸"（签出隐藏）；同日即推翻——开关整体移除（见 [移除工作树勾选开关](2026-09-14-worktree-toggle-removed.md)），两个动词改为 `canWorktree`（`session.blank && !inLinkedWorktree`）门控**追加**进六动词集，位置在**新建并检出之后**（隔离读作分支的加重变体）：「创建工作树」（非当前行；owner 的 `onWorktree` 直弹 reuse/新建/远程孪生确认——刻意不走 `pick`/`onSelect`，那条路是原地签出）与「新建分支并创建工作树」（含当前行——切出正是隔离动作，owner 的 cutout 弹窗、名字手输；`git worktree add <path> -b <name> <base>` 的 `base` 本就是任意起点参数，后端零改动）。已开始的会话动词隐藏（目录已固定），与「工作树」跳转分组同一门控。
- **工具条加号退场**：原"从当前分支原地新建"的工具条入口整体移除——右键当前分支行的"新建并检出"就是原地建 + 切（同 git 形态），同一个动作不需要两个入口；工具条只剩只读工具（定位/更新/提取/折叠）。代价：detached HEAD 的原地新建入口随之消失（右键行需要行名，detached 无行）——`from` 路由形态保留，终端兜底。
- **keep-open：原地动作不收菜单**：签出、新建、新建并检出、重命名、删除成功后分支菜单**保持打开**（列表刷新、行随事实更新），用户可以连续操作多行；确认弹层/创建/重命名弹窗各自收起。只有**会话跳转类**动作（工作树直跳、worktree 创建/复用）仍然关闭整个菜单——会话都换了，菜单无所依附。创建/重命名弹窗的成功收起走 owner 的 success-only `onSettled` 钩子（失败跳过，弹窗保留改名重试）。
- **双击退场**：`onDoubleClick` 绑定整体移除，鼠标执行路径收敛到右键菜单、键盘路径保持 Enter（选中行回车 = 原双击同款 `pick`）。右键菜单项与被移除的双击走的是同一个 `pick`/弹窗目的地，删的是通道，不是语义。文件夹切换后的 CLICK_GUARD 布局位移防护保留（急速连点仍会误触滑动进光标下的行，与双击无关）。
- **不打自己的语义**：右键打开菜单不选中、不布防 shift-guard（菜单不移动布局）；Escape 顶层档位、卡片外点、行点击均先撤菜单——卡片内点击只关菜单不关整个 picker，菜单自身挂在外点豁免名单（与卡片、两个弹窗同待遇）。
- 浏览器原生右键只在行上被抑制；组头、工具条、搜索框保留原生行为。
- 三种行形态的指针事件四件套（click/hover 进出/contextmenu）本就逐字重复三遍，收敛为 `rowEvents` 一处。

## Alternatives considered

- **右键与双击并存**（增强初版的形态）——同一个动作两条鼠标触发路径，双击的可发现性短板原封不动，还要为"右键有而双击没有"的动作（新建、重命名）维护第二套无入口的暗示；通道冗余不是慷慨是负担。放弃，右键菜单落地后双击整体退场。
- **单击即执行**（VS Code 模型）——能消灭选中态管理，但确认弹层的锚定流（选中 → Enter/右键执行）已覆盖鼠标与键盘；单击执行会让"扫视列表点选对比"变成一连串确认弹层。放弃。
- **复用基础库 `Menu` 原语渲染右键菜单**——其定位锚定 anchor 元素，无光标坐标锚定；本菜单的浮层家族（卡片/确认弹窗/创建弹窗/重命名弹窗）已是手写 measure-then-place 姿势，右键菜单沿用同一姿势更一致。放弃。
- **重命名并入 `/branch` 路由**（加 `action` 键区分建/改）——建与改的参数形状不同（起点 vs 新名），一个路由两种语义只会让校验矩阵分叉；独立 `/branch-rename` 与 `/switch`、`/fetch` 的"一个动作一条路由"口径一致。放弃。
- **新建并检出加第二段确认**——它会动检出，看似该确认；但创建弹窗"敲下名字即意图"的一把式决策（[原地新建分支](2026-08-30-create-branch-in-place.md)）已覆盖"带输入的动作免二次确认"，新建并检出只是多了个起点参数，风险面与加号完全一致。放弃，保持一把式。

## Consequences

- 得：行级动作有了可发现的容器；"复制分支名/工作树路径""从任意分支开新线、给任意本地分支改名"全部不出菜单（服务端只加一个可选 `from`/`checkout` 键和一条 `/branch-rename`，弹窗/校验/单飞全部复用）；双击退场后触发通道收敛为"单击选中 + Enter/右键执行"一句话可述，`rowEvents` 顺带把三处重复的行事件净减为一处。
- 代价：多一层 portal 与一套关闭档位（Escape/外点各加一支），浮层家族多一个重命名成员（状态、放置、Escape 各一档）；`POST /branch` 三形态（无 `from` = 建 + 原地切；`from` = 只建不切；`from` + `checkout` = 建于起点并检出），调用方必须分清——客户端以入口区分（工具条加号恒为第一形态，右键恒带 `from`）；鼠标最快路径从双击变为右键（一下变两下），换来的是动作显式可见。
- 边界：**纯触屏无右键**，鼠标/键盘之外没有第三通道——触屏用户只剩 Enter（需先聚焦行）与工具条，这是本决策最大的可及性让步；右键菜单无键盘路径（Shift+F10/Menu 键未接）；复制与 `from` 用的是显示名/动作名的现行映射——单远程下复制丢 `origin/` 前缀（与"所见即所复制"一致），而 `from` 交的是真实动作名（`git branch` 需要它）；`from` 只建不切时新分支要自己在列表里找（按 `/` 前缀归组，通常就在起点旁边）；重命名在 git 拒绝（目标重名、非法名）时 400 toast、弹窗保留重试，而"被 worktree 占用"git 自身允许（HEAD 随引用走）——不额外设防；"签出"对 locked 行仍然可点，语义与行点击一致（owner 以 main-checkout toast 应答）。
