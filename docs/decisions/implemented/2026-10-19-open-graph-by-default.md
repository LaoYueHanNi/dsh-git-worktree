# DR: 分支图标可默认打开图谱

Status: implemented

## Problem

点击对话框里的分支图标总是先打开紧凑的分支菜单，看提交图谱还要再点一次左侧按钮。有人希望这一下就进入图谱，但不能把这个行为加给所有人。

## Decision

插件设置增加 `openGraphByDefault`（界面文案“默认展开 Git 图谱”），默认关闭，和“创建工作树前同步上游”一样立即写穿。开关放在设置页“管理工作树”之上。写穿失败时在开关下显示重试提示。

关闭时沿用既有行为：分支菜单第一次是紧凑列表；用户用左侧按钮打开图谱后，关掉浮层再点分支图标，图谱模式仍然保持。

开启后，分支菜单从关闭变为打开的那一次直接进入图谱，不先画出紧凑菜单再展开。菜单已经打开时，左侧按钮仍可收起图谱。收起之后只要菜单还开着就保持收起；关掉菜单再点分支图标，只要设置仍开着，再次以图谱打开。设置在菜单打开期间被打开，不改当前这次浮层，下一次点击才生效。

宿主配置项为 volatile 布尔值，缺省按关闭投影到设置表单。分支芯片在每次渲染时读取当前快照，不把打开时的值钉死在组件挂载上。

## Alternatives considered

**设置关闭时也每次按设置重置图谱模式**：会清掉用户手动打开并希望保留的图谱，推翻关闭浮层不重置模式的约定。设置关闭时继续保留该记忆。

**只在芯片第一次挂载时读设置**：芯片在会话期间一直挂着，改完设置要点一次分支图标才该生效，但不能要求刷新页面。每次打开菜单时读取当前值。

## Consequences

打开该设置后，上次在浮层里收起图谱不会带到下一次点击分支图标。关闭该设置时，手动打开过的图谱仍会在重开浮层后保留。设置未就绪或宿主没有这个字段时按关闭处理。写穿失败不会悄悄弹回而不提示。
