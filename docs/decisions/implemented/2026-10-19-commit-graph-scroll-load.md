# DR: 提交列表滚到底自动加载

Status: implemented

## Problem

提交图谱每页 100 条。后续页只放在列表外面的“加载更多”上，滚到已加载提交的末尾不会继续，必须离开滚动去点按钮。

## Decision

本记录扩展[从分支菜单原位展开提交图谱](2026-10-18-branch-commit-graph.md)的分页触发方式，分页大小、tip 固定和底部按钮的显示条件不变。

提交列表自身滚动，且内容高出可视区域时，距底部不超过 8px 即用当前 tip 与 `next` 请求下一页。加载中、没有下一页、或这一页已经失败时不自动请求。失败仍由底部“重试”手动发起。列表没有溢出时不自动连拉，底部“加载更多”仍在，供筛选后装得下的列表和明确的再试使用。

同一次分页偏移在对应响应落定前不会再发请求。滚动事件会在下一次绘制前重复触发，提前清掉这个偏移会把同一页再请求一次并追加出重复提交。切换分支、刷新会放弃该偏移和未完成的请求。

## Alternatives considered

**只保留底部按钮**：滚到末尾仍要停下来点，和顺着列表往下翻历史是断开的两步。

**末端只要可见就加载，包括列表没有溢出**：作者或文本筛选只命中很少提交时，列表底部一直可见，会在没有滚动的情况下把整段历史拉完。

**自动加载后去掉“加载更多”**：没有溢出的列表没有可滚的末端；失败页如果跟着滚动重试，会把一次读取错误打成连续请求。

## Consequences

长历史可以顺着滚动继续读，已加载行的图谱节点不会因追加而移动。筛选后的短列表仍要点按钮才会继续，搜索范围也仍只覆盖已加载提交。停在末端会多打一次 `/history`；失败不会自己重试。滚轮在绘制前的重复事件不会打出重复页。
