# DR: 勾选工作树即弹切出确认，「从当前分支切出」派生 -wt 新分支

Status: implemented

## Problem

空白会话上勾选「工作树」只设置一个前端模式位：不打开菜单、不发起任何请求。创建 worktree 的唯一路径是再选一个**非当前**分支并确认。用户勾选后直接发送消息时，会话启动 effect 会把勾选静默清掉——隔离承诺没有兑现、也没有任何提示，用户可能误以为代码变更发生在隔离目录，实际落在主 checkout。而"勾选后选当前分支"这条路径根本不存在：当前分支被主 worktree 检出，`git worktree add <路径> <当前分支>` 必然被 git 拒绝，选中它只关闭菜单。

## Decision

把提示从"事后"移到"勾选时刻"，并让当前分支成为可切出目标：

- **勾选即确认**：勾选「工作树」立即在分支 chip 上方弹出「从当前分支切出」确认弹窗（独立于分支菜单，确认即切出），不展开菜单、不加行内徽标——引导就是弹窗本身。分支菜单仍由点击分支 chip 打开：选其他分支是原 create-or-reuse 确认流，菜单里重选当前分支同样进入切出确认。
- **从当前分支切出 = 派生新分支**：确认"从当前分支切出"后，host 端生成 `git worktree add <目标> -b <新分支> <当前分支>`。新分支名**在确认弹窗中可编辑**（2026-08-30 修订：初版固定 `<当前分支>-wt` 不可改名）：预填第一个空闲的 `<当前>-wt` 名（前端对照本地分支表，与 host 端 `cutoutBranchName` 同形但不含存储目录探测），用户可改成任意合法名字——校验与新建分支弹窗同款（git ref-name 规则 + 与现有分支查重，重名/非法禁用确认）；显式名字经 `POST /worktree` 的可选 `name` 键直达 host、跳过后缀巡检，分支与存放目录都用它；缺省仍自动派生，与 `refs/heads` 冲突时自动递增 `-wt2`、`-wt3`…（一次 `for-each-ref` 决定）；自动名必须在**两个命名空间**同时空闲——分支表之外，存放目录被残留目录占用（分支已手工删除、目录还在盘上）时同样跳到下一个后缀，否则 `worktree add` 会因目录已存在而硬失败；存放目录名用**新分支名**（`<仓库>-<新分支>`），因为新分支才是该 worktree 的身份。切出不复用：每次确认都切出一个新分支。
- **不选分支直接发消息 = 知情默许**：切出确认已弹出过，用户取消（或忽略）后直接发送消息即视为主动留在当前目录，发送时不弹任何补充提示。
- **协议**：`POST /worktree` 增加可选布尔 `cutout`；host 新增 `cutoutBranchName`/`addWorktreeCutout`，`readBody` 支持可选布尔键（缺省即缺省，出现必须为 boolean）。非 cutout 路径与旧客户端完全兼容。

## Alternatives considered

- **发送消息时若勾选未兑现则 toast 警告**——提示发生在决策时刻之后，用户已经"发出去了"，且勾选本身仍无引导；用户在意的场景（不选分支直接发消息）被明确为默许行为。否。
- **`git worktree add --detach` 检出当前提交**——不产生分支：无法提交、无分支可追踪，失去"分支"心智模型，污染后无从合并。否。
- **切出用固定分支名、冲突时直接报错**——`main-wt` 残留时第二次切出即失败，用户须手动清分支；自动递增无此打断。否。（2026-08-30 进一步修订：自动名保留为**预填值**，弹窗内可编辑成任意合法名——固定不可改的自动名覆盖不了"自定义名 + 工作树"一步到位的场景。）
- **存放目录残留时报错让用户手动清理**——报错对用户没有行动指引（目录是谁留的、删了安不安全都不可知），且与分支冲突的自动递增处理不一致；跳名与「切出不复用」的语义天然契合，残留目录留给用户自行处置。否。
- **勾选即立即按当前分支创建 worktree（跳过选择与确认）**——创建目录、注册 workspace、跳转会话语境是重决策，需要确认；且用户勾选后可能只想先看看分支列表。否。

## Consequences

- 代价：每次切出都会产生一个新分支名（`-wt`、`-wt2`…），与"选分支复用"的天然幂等不同，用户需要在 git 里管理这些派生分支；确认弹层文案新增一条 cutout 变体，i18n 相应扩大；切出确认弹窗与菜单 flyout 是两处渲染（共享同一份 confirm bundle 与 popCard 样式），交互面多了一个组件。
- 所得：勾选动作有了即时、聚焦的反馈与路径（消除无声失败）——确认弹窗直达决策点，不要求用户先理解一张分支列表；当前分支首次成为可隔离目标，覆盖"我在 main 上但想隔离着干"的最常见场景；发送消息不再需要事后补偿提示，交互路径只有一条：勾选 →（切出/选分支/放弃）。
