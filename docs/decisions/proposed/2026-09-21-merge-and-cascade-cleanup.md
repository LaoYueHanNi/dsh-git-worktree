# DR: 支持工作树删除时级联清理分支与快进合并清理工作流

Status: proposed

## Problem

在当前工作树生命周期管理中，删除工作树（`removeWorktree`）只销毁工作树物理目录与 Git 工作树登记，并归档关联会话与注销 DSH 工作区，而检出的本地分支始终保留在仓库中。这导致用户在频繁为临时任务或特性创建工作树后，仓库中残留大量废弃的本地分支，需要手动去分支列表中逐个删除。

此外，当用户在独立工作树中完成开发后，需要先切换回主检出目录手动执行合并，再回过头来删除工作树和分支，缺乏一站式的“合并完成即清理”的工作流闭环。

## Proposal

提供两套互补的级联清理能力：

### 1. 工作树删除确认弹窗增加级联删除分支选项

- 在工作树删除确认弹窗（`ChipConfirm`）中增加「同时删除本地分支」勾选框，默认不勾选以防止误删。
- 分支删除安全门控：
  - 若分支已完全合并（符合 `git branch -d` 安全语义），在工作树移除成功后自动执行删除。
  - 若分支包含未合并的提交，弹出二次警告并显示领先提交数，需用户显式二次确认才执行强制删除（`-D`），未确认则保留分支。

### 2. 工作树行新增「合并到当前分支并清理」显式动词

- 在未被该工作树占用的检出目录（如主工作树）的分支菜单中，针对工作树行提供「合并并清理」操作。
- 执行顺序与原子门控：
  1. **前置检查**：检查工作树是否有未提交的脏文件（dirty > 0），有脏文件则立即拒绝，避免代码丢失。
  2. **快进合并**：在当前检出目录执行 `git merge --ff-only <branch>`。若遇到分叉、冲突或非快进，操作立即安全中止，保持现场不变，绝不留下冲突标记或脏提交。
  3. **级联清理**：合并成功后，触发完整删除流程（物理移除工作树目录、注销 Git 登记、归档关联会话、注销 DSH 工作区），最后调用分支删除接口删除已完全合并的本地分支。

## Alternatives considered

- **默认勾选「同时删除本地分支」** —— 虽然多数临时工作树的分支随着工作树废弃而不再需要，但默认勾选极易导致用户习惯性敲击确认键误删尚有保留价值的本地分支，安全优先级高于便捷性。
- **未合并分支一律严格拒绝（不允许二次确认 `-D`）** —— 过于死板；当用户明确知晓该分支是废弃的试验代码且希望彻底销毁时，若不允许强制删除，用户仍需去终端手动输入 `git branch -D`，违背了一站式清理的初衷。
- **合并并清理支持三方合并（生成 merge commit）或自动暂存** —— 自动合并若产生冲突会进入 Git 冲突解决态，破坏当前工作区的干净环境；快进合并（`--ff-only`）具有纯粹的无害性，要么完全成功，要么保持原状。
- **仅提供合并清理动词，不改动已有删除弹窗** —— 无法覆盖不需要合并、直接废弃工作树场景下的分支清理需求。

## Acceptance criteria

1. 在分支菜单或管理弹窗中删除工作树时，确认弹窗显示「同时删除本地分支」勾选框，且默认处于未勾选状态。
2. 勾选后执行删除，若分支已合并，工作树与分支一并清除，Toast 提示完整清理结果。
3. 勾选后执行删除，若分支未合并，展示未合并二次确认弹窗；若取消则只删除工作树保留分支，若确认则强制删除分支。
4. 在当前检出目录右键工作树行，提供「合并并清理」动词；有未提交改动时禁用或提示拒绝。
5. 「合并并清理」执行 `--ff-only`，遇冲突/分叉报错并完整保留工作树与分支；快进成功后自动清理工作树、归档会话并删除分支。
6. 测试覆盖两阶段删除中的分支级联逻辑、未合并拦截与强制删除分支逻辑、快进合并与拒绝逻辑。

## Risks

- **当前 HEAD 与目标分支状态漂移**：快进合并必须保证当前目录干净且处于预期的目标分支上，若当前目录自身存在未提交的修改，`--ff-only` 会被 Git 原生拒绝，需要友好清晰地转译 Git 错误。
- **误删未推送分支**：即使分支已合并到本地 HEAD，可能尚未推送到远程；二次确认提示文案需准确呈现该分支的状态。
