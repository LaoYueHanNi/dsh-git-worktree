# DR: 利用原生会话菜单插槽支持工作树行级快捷操作

Status: proposed

## Problem

在插件 0.1.6-alpha.2 的迁移中（见 [DR: 适配宿主 dsh 0.1.6-alpha.2](../implemented/2026-09-19-migrate-to-dsh-0.1.6-alpha.2.md)），为了跟随宿主架构演进，本项目废弃了容易导致 UI 割裂和维护成本失控的侧边栏整块遮蔽（`priority: -1`），将侧边栏完全交还原生 `ui-workspace`。

然而受限于 0.1.6 宿主的能力边界——当时宿主仅开放了 `directoryFlow` 单槽位，缺乏会话行级扩展点，导致插件无法在原生会话列表的右键菜单中注入任何菜单项。用户若要删除某个工作树，只能通过分支菜单的「工作树」分组行右键，或前往 Plugins 设置页打开「工作树管理弹窗」进行清理。这导致用户在侧边栏浏览某个具体会话时，无法直观对其所在工作树进行销毁或归档，交互路径偏长且存在场景割裂。

上游宿主在 `0.1.7-alpha.1`（PR #4427）中正式补齐了这一扩展能力，开放了两个行级插槽：
- `sidebar.workspaces.session.menu.item`（会话 "..." 弹出菜单项列表）
- `sidebar.workspaces.session.row.action`（会话行悬停快捷按钮列表）

## Proposal

利用宿主新开放的行级插槽，无侵入地将工作树操作接入官方原生会话菜单：

### 1. 动态行级感知与菜单注入

- 在 `src/client/index.ts` 中通过 `ctx.slots.inject('sidebar.workspaces.session.menu.item', ...)` 注册菜单项。
- 注入项接收 `{ sessionId, displayTitle }` 及 `useMenuOpenState` 钩子。
- 菜单项根据 `sessionId` 向上反查其所属工作区：
  - 读取当前工作区的 `path` 并结合 `worktrees-all` 或本地探测判断该目录是否属于 linked git worktree；
  - **非工作树会话**：组件直接返回 `null`，完全不打扰普通会话与主仓库会话；
  - **工作树会话**：渲染带有宿主原生样式的 `role="menuitem"` 按钮（可复用 `MenuItemButton`），文案为多语言字典中的「删除此工作树」。

### 2. 菜单位置与视觉规范

- 指定合理的 `order`（例如 500，紧跟在宿主内置的 `pin` [100]、`rename` [200]、`fork` [300]、`archive` [400] 之后）。
- 设置 `separatorBefore` 分割线，使其作为独立的危险/扩展操作区呈现，符合宿主视觉层次。

### 3. 复用安全删除生命周期流

- 点击后先调用 `setMenuOpen(false)` 收起原生菜单，随后拉起共享的删除二次确认弹窗。
- 弹窗完整沿用现有的 [`removeWorktreeFully`](../../../src/client/worktree-remove-flow.ts) 安全检查：
  - 检查工作树是否存在未提交的修改（dirty）；
  - 检查是否存在未推送的领先提交（ahead）；
  - 检查会话是否正在运行（运行中禁用删除）；
  - 列出关联将归档的会话总数；
- 用户确认后执行 Git worktree 移除、归档关联会话并注销工作区。

## Alternatives considered

- **在 0.1.7-alpha.1 升级的同一提交中合并实现** —— 违反单一职责与风险隔离原则。0.1.7 升级的核心目标是消除破坏性断代（Settings 重构）并保证基座可用；行级菜单扩展涉及独立的组件封装、状态缓存、多语言与交互测试，应作为后续独立的特性 PR 交付。
- **重新搞侧边栏整块遮蔽（priority: -1）** —— 0.1.6 已经明确否决该方案。原生槽位已开放，无需再为了增加一个菜单项而去复刻整套官方侧边栏。
- **仅保留工作树管理弹窗，不向侧栏注入任何操作** —— 交互路径冗长。用户在左侧侧栏定位到某个已完成的临时分支会话时，最自然的心理预期就是直接右键删除该工作树，保留弹窗作为集中管理面板、会话菜单作为快捷入口，二者互为补充。

## Acceptance criteria

1. 在官方原生侧边栏的会话 "..." 菜单中，属于工作树的会话可见「删除此工作树」操作项。
2. 非工作树会话的右键菜单保持纯净原生状态，不出现多余菜单项与空行。
3. 点击菜单项后调起标准二次确认弹窗，能准确提示脏文件、领先提交及将归档的会话。
4. 确认删除后安全清理 Git 引用、归档会话并移除对应工作区，删除过程中有加载中状态防重入。
5. 补充单测验证会话属于工作树时的挂载逻辑、非工作树时的空渲染逻辑，以及点击触发的确认流。

## Risks

- **频繁探测的性能开销**：会话菜单展开时若高频调用后端 Git 命令会导致界面卡顿；应优先复用前端 live store 中的工作树路径集合进行轻量纯内存匹配，避免在菜单 render 时触发后端 spawn。
